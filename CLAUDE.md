# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Claude Code plugin marketplace (`skogai-marketplace`). No build or test suite. `.claude-plugin/marketplace.json` is generated by `scripts/generate-marketplace-json.sh` from `.claude-plugin/marketplace-header.json` (top-level fields), `plugins/*/.claude-plugin/plugin.json` and `.claude-plugin/external-repos.json` (plugin source objects); never hand-edit it. `scripts/generate-marketplace-json.sh --check` fails if it drifted; the `marketplace` GitHub workflow and `scripts/git-hooks/pre-commit` (`git config core.hooksPath scripts/git-hooks`) run it.

## Layout

- Local plugins live under `plugins/` and are listed with a `./plugins/<name>` source. No `metadata.pluginRoot` and no bare names: claude.ai organization sync rejects them. External plugins (no submodules) are listed in `.claude-plugin/external-repos.json`. An external repo without `plugin.json` gets its name and description from the `"./"` entry in its own `.claude-plugin/marketplace.json`, plus `"strict": false`, which organization sync requires for an inline manifest.
- Marketplace entries carry only `name`, `source`, `description` (and `strict` in that one case); `name` is kebab-case and matches the directory. Versions go in each plugin's `.claude-plugin/plugin.json`, not the marketplace entry.
- `docs/` is a synced snapshot of the Claude Code docs (date in `docs/synced-at.txt`). Treat it as the read-only reference for plugin/hook/marketplace APIs; never edit it.
- `CONVENTIONS.md` documents this repo's conventions and how the generator works.
- `apm.yml` is a learning test of apm (`~/.local/src/apm`): `apm pack` writes the same entries to `build/apm-marketplace.json` (gitignored) for comparison. The generator stays the source of truth; apm has no `strict` or `renames`, and `targets:`/`dependencies:` in `apm.yml` make `apm pack` write a root `.claude-plugin/plugin.json`.

## Validating

- `claude plugin validate plugins/<name>` — run after changing a plugin or its marketplace entry. `skogai marketplace check [name]` does that plus the generator `--check` (a local module, `.skogai/modules/marketplace/`; `skogai` is skogai-runner's, see its `module` skill).
- `claude -p "reply with just OK" --plugin-dir plugins/<name>` — headless load check.
- `plugins/skogai-core/LEARNINGS.md` lists function-hook validator rules (string-literal event names, function-literal hooks, `$.noun.method()` only; one throwing hook stops the whole module loading). Read it before writing TypeScript hook modules.
